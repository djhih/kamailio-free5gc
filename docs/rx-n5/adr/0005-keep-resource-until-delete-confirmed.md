# ADR-0005：刪除未確認前保留資源 URI 並有限重試

- 狀態：提案
- 日期：2026-10-22
- 取代：v0.1 設計 §6.3 的「PCF 刪除失敗只記 log，照樣刪掉 session、回 STA 2001」

## 背景

刪除 app session 失敗時，如果 Adapter 丟掉 session 紀錄，資源 URI 就沒有任何地方記得，PCF、SMF、UPF 上的語音規則會一直留著。每次失敗的測試都可能讓後面的測試結果受污染。

## 決定

- 刪除逾時或可重試錯誤時，session 轉為 `DELETE_PENDING`，保留 URI。
- 首次失敗後最多重試 5 次，間隔 1／2／4／8／16 秒加 jitter，只重試可重試的錯誤。
- 重試耗盡後告警並等人工處理；待清理紀錄不因 TTL 自動刪除。
- 404 只有在「資源確實不存在」時才算清理成功（REQ-STR-03）。

## 後果

- 留下的資源一定能被找到並清掉。
- session store 必須能保存 DELETE_PENDING 的紀錄；要通過重啟測試就需要持久化（D06）。
- STA 在刪除未確認時要回什麼，依 D02 決定（REQ-STR-06）。
- 對應需求：REQ-STR-02、03、REQ-CFG-02；測試：T11、T22。
