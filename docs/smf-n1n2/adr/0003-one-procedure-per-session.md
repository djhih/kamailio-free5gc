# ADR-0003：每個 PDU session 同時只進行一個網路發起修改程序，其間的差異排隊合併

- 狀態：提案
- 日期：2026-10-22

## 背景

- 一通電話會在短時間內產生兩次 policy 更新（200 OK 時新增、BYE 時刪除）；通話很短時，刪除可能在新增程序結束前就到（[design.md](../design.md) §5.4）。
- TS 24.501 V17.18 §6.3.2.5 只規定了 UE 發起的釋放、修改與網路發起修改相撞時的處理，沒有規定兩個網路發起修改重疊。
- SMF 現有的 T3591 是每個 SM context 一個（`smContext.T3591`）。

## 決定

每個 PDU session 同時最多一個程序。PENDING 期間的 policy 更新照常套用到 UPF，但差異排進 `queued`，程序結束後一次送出。同一個 QFI 先新增後刪除：新增還沒送出就抵銷；新增已在途就等它完成後再送刪除。

## 後果

- 好處：RAN／UE 不會同時收到兩個彼此依賴的修改；T3591 與回應比對都只有一份。
- 代價：刪除可能延後一個程序的時間；這段期間 UPF 已刪規則、RAN 還保留資源。
- 對應需求：REQ-ST-01、REQ-ST-02；測試：T16、T18
